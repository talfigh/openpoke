OpenPoke routing eval · offline, synthetic inbox · 27 Oct 2026

Agent naming and overload

Does OpenPoke send a request to the right execution agent when it already has dozens or hundreds of them? And do the results change if OpenPoke names the agents itself, or if the user words the request differently?

Model unchanged for every run: anthropic/claude-haiku-5.5 via OpenRouter. No real email was read or sent. Gmail calls were answered from a fake Composio backend.

What we found

Overload 74% → 59%

Routing accuracy drops as the roster grows from 40 to 500 agents. It drops under every naming style and every wording we tested.

Wording ±3 points

Paraphrasing the prompts barely moves the score. The same cases fail under every rewording, so the failures are structural, not luck.

OpenPoke's names help Lookalikes 100%

OpenPoke puts the full person name in each agent name, so it never mixes up two clients with the same first name, even at 500 agents.

…and hurt Reminders 30% → 15%

Its names describe the task, not the topic you'd mention later. Reminders and new jobs get a new agent or land in the wrong one more often.

Neither naming style fixes routing. With a long roster, both reach about 37% duplicate agents on follow-ups. The likely fix is in how agents are found (search over agent metadata and history), not in what they are called.

How the test works

The roster

The roster is OpenPoke's list of existing execution agents. The Interaction Agent sees only their names and picks one by exact name, or creates a new agent.

Every roster holds the same 40 core agents, which are the ones the test prompts are about. Larger rosters add filler: other client work and older finished jobs that no prompt targets. Only the amount of filler changes, so any score change comes from roster length.

Why naming trades one failure for another

Lookalikes get easier

Every OpenPoke name carries the full person name. "Priya Santos" and "Priya Sharma" never look alike, so lookalike cases score 100% at every size. Generator names sometimes use a first name only or the company only, and they drop from 86% to 58%.

Reminders get harder

OpenPoke names commercial work by company and task. A reminder that uses the client's first name doesn't match the agent name, so OpenPoke creates a fresh agent for the reminder. The reminder then fires in an agent that knows nothing about the work.

"remind me Wednesday at 10am to check that Maya's certificate was issued" → new agent Maya Certificate Check Reminder, instead of the existing Cardenas Bakery COI Regional Municipality of York.

A clear name match doesn't always help. With this roster, OpenPoke often treats a reminder as a job of its own:

"remind me tomorrow at 10am to check that Daniel's certificate went out" → new agent Daniel Okafor Certificate Reminder, although Okafor Landscaping COI City of Vaughan already exists.

New jobs merge more often

The reverse also happens. A surname-only request for a different job ("the Cardenas renewal") matches the company agent, so new work lands in the old agent. Shared details pull in wrong matches too: "Ines's certificate for Dufferin Plaza" went to another client's …Certificate Request Dufferin Plaza.

Names can't carry the whole job

About a third of follow-ups refer to work in a way the agent name doesn't contain, such as "Ana's certificate" for MacLeod Print Shop Ltd. COI. Name-only routing reaches 20–44% on those, whoever writes the names. The Interaction Agent needs more than a list of names to route them.

How far to trust these numbers

  • Run-to-run noise is about ±2 points on overall accuracy. The generator-names, original-prompt line is the mean of 3 runs. The other three conditions are single runs, but the paraphrase conditions have about 3× as many prompts.
  • Small groups swing a lot. Ambiguous (7 cases) and lookalike (12) can move 20–40 points between runs. Compare the overall and reuse lines first.
  • Failed API calls are excluded. 6 of about 2,700 calls failed (OpenRouter credit ran out during one sweep). Sizes 100–500 for the OpenPoke-names and paraphrase conditions were rerun after a top-up.
  • Synthetic data. The inbox, clients and test prompts are invented: 995 emails across 609 threads, covering 90 days of a Toronto insurance broker's mail. The patterns should transfer, but the exact percentages belong to this dataset.
