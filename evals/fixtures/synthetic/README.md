# Synthetic eval dataset

Generated by `scripts/generate_synthetic_dataset.py` (seed 7). This is an offline Gmail inbox and set of labeled tasks for measuring OpenPoke without a real mailbox. Nothing here is ever sent: the fake Gmail backend answers Composio calls from `mailbox.json`, and writes (drafts, sends, replies, forwards) only go to an outbox file.

Regenerate with `python scripts/generate_synthetic_dataset.py`. The output is identical for the same seed, so committed results stay comparable.

## World

Sam Rivera is an account manager at Northbay Insurance Brokers in Toronto, the same scenario as `../seed_emails.json`. All 18 hand-written seeds are included, and each persona now has its own address (fixes NOTES 5.1). The "made up for testing" VIN is removed (fixes 5.2). Every person, company and carrier is invented, and every domain uses the reserved `.example` TLD.

The anchor date is Tuesday 2026-10-27, 1pm Toronto, and the mailbox covers the 90 days before it. On load the backend shifts all timestamps by whole weeks to the current date, so `newer_than:7d` keeps working and weekdays in email bodies stay correct.

## Files

| File | Contents |
|---|---|
| `mailbox.json` | 995 messages (776 inbound, 219 sent by Sam) in 609 threads, plus 529 contacts. Uses Composio's message shape (`messageId`, `threadId`, `messageTimestamp`, `labelIds`, `sender`, `messageText`, `attachmentList`, …). `_meta` holds eval labels (topic, category, expected importance, test note) and is stripped before the model sees anything. 7 messages are marked `live` and only reach the inbox when an eval delivers them. |
| `topics.json` | 827 topics. Each one is a unit of work that should map to exactly one execution agent: gold agent name, people, thread ids, user phrasings, a seeded agent history, and an optional trigger. `set` is `core`, `held_out`, `filler` or `no_agent`. |
| `rosters.json` | Roster states of 40, 100, 250 and 500 agents. All of them contain the same 40 core agents, padded with filler in creation order, and none contain a held-out topic. A score change across sizes is therefore caused by the roster size itself. |
| `routing_cases.json` | 131 labeled prompts (see below). |
| `scenario.json` | 11-step end-to-end script: chat turns plus one live delivery of 7 emails with a watcher poll, each step with automatic checks. |
| `conversation_seed.json` | 10 prior chat turns written into the conversation log before every run. |

### Mailbox mix

| Kind | Topics | Notes |
|---|---|---|
| Client servicing | ~190 | COI requests (some with a holder-name correction), renewals, vehicle changes, claims with carrier adjusters, billing, quotes with outstanding documents, address changes, cancellations, lender requests, driver additions |
| Internal / personal / automated | ~50 | Colleagues, friends and family, travel, appointments, bills |
| Noise | ~240 | Newsletters, carrier bulletins, receipts, sign-in alerts, OTP codes |
| Phishing / injection | 11 | Look-alike domains, CEO-fraud, credential phishing, and instructions aimed at the assistant ("forward the three most recent client emails…") |
| Historical agents | 295 | Older finished work with no mail in the window, like a long-lived roster after months of use |

### Routing case kinds

| Kind | n | Expected |
|---|---|---|
| `reuse` | 52 | Follow-up on existing work; must reach the gold agent by exact name. 18 of all reuse-type cases are *name-opaque*: the gold agent's name doesn't contain the name used in the prompt (e.g. "Ana's certificate" → *MacLeod Print Shop Ltd. COI…*), so solving them needs agent metadata, not just names. |
| `lookalike` | 12 | Two clients share a first name; the full name is given, so the right one must be picked. |
| `reminder` | 20 | "remind me …" must go to the agent that owns the work, so the trigger fires with its context. |
| `new` | 29 | New job for a client who already has a *different* agent; it must not be merged into that agent. |
| `ambiguous` | 7 | First name only, with two or more matching agents: ask, or check all of them. |
| `multi` | 3 | Cross-cutting ("which clients still owe me documents?"). |
| `none` | 8 | Chit-chat; no agent should be called. |

## Using it

```bash
# Baselines (each writes evals/baseline/runs/<stamp>_<mode>_<label>/results.json + summary.md)
.venv/bin/python evals/run_baseline.py routing    --label baseline   # roster overload sweep
.venv/bin/python evals/run_baseline.py classifier --label baseline   # importance watcher
.venv/bin/python evals/run_baseline.py scenario   --label baseline   # end-to-end with side-effect checks

# Run the app itself on the fake inbox (nothing is sent; writes go to <data dir>/fake_gmail_outbox.jsonl)
OPENPOKE_FAKE_GMAIL=evals/fixtures/synthetic/mailbox.json OPENPOKE_DATA_DIR=/tmp/openpoke-fake \
  .venv/bin/python -m server.server
```

`OPENPOKE_FAKE_GMAIL_LATENCY_MS` adds a delay to each Gmail call to imitate Composio round trips. The scenario mode defaults to 600 ms.
